Documentación del Proyecto Blockchain PHP

Introducción

Este documento detalla la arquitectura, funcionalidades y componentes del Proyecto Blockchain PHP. El objetivo de este proyecto es crear una aplicación web completa que integra una blockchain funcional con características modernas como un sistema de usuarios, una galería de videos de YouTube y una lista de tareas.

La aplicación utiliza un stack tecnológico clásico pero potente:

  • Backend: PHP para toda la lógica del servidor.
  • Frontend: HTML, CSS y JavaScript vainilla (puro) para la interfaz de usuario.
  • Base de Datos: MySQL para persistir los datos de usuarios, tareas y la propia blockchain.
  • Comunicación: La comunicación entre el frontend y el backend se realiza mediante peticiones AJAX (usando la API fetch de JavaScript) que intercambian datos en formato JSON.

Configuración e Instalación

Sigue estos pasos para poner en marcha el proyecto en un entorno de desarrollo local.

1. Requisitos

  • Un servidor web local como Apache o Nginx.
  • PHP (versión 7.4 o superior recomendada).
  • Servidor de base de datos MySQL (o MariaDB).
  • Una herramienta de gestión de bases de datos como phpMyAdmin (recomendado).

2. Configuración de la Base de Datos

Primero, necesitas crear la base de datos y sus tablas.

  1. Accede a phpMyAdmin (o a tu cliente de MySQL preferido).
  2. Crea una nueva base de datos llamada proyecto_blockchain_php.
  3. Importa el archivo database.sql en la base de datos recién creada. Este script creará las tablas users, tasks y blockchain con la estructura necesaria.

3. Configuración del Backend

El único archivo que necesitas configurar es el que contiene las credenciales de la base de datos.

  1. Abre el archivo api/config.php.
  2. Modifica las constantes DB_HOST, DB_USERNAME, DB_PASSWORD y DB_NAME para que coincidan con tu configuración de MySQL. Por defecto, está configurado para un usuario root con contraseña root. 
    // api/config.php
<?php
// Database Configuration
define('DB_HOST', 'localhost');
define('DB_USERNAME', 'root');
define('DB_PASSWORD', 'root'); // <-- Cambia esto si tu contraseña es diferente
define('DB_NAME', 'proyecto_blockchain_php');

4. Ejecutar el Proyecto

Copia toda la carpeta proyecto_blockchain_php en el directorio raíz de tu servidor web (por ejemplo, /var/www/html/ en Linux o C:\xampp\htdocs\ en Windows con XAMPP).

Abre tu navegador web y navega a http://localhost/proyecto_blockchain_php/. Serás redirigido a la página de inicio de sesión.

Análisis del Backend (PHP)

El backend es el cerebro de la aplicación. Está escrito en PHP y se encarga de procesar todas las solicitudes, interactuar con la base de datos y ejecutar la lógica de la blockchain.

Autenticación de Usuarios

Registro: api/register.php

Este script maneja el registro de nuevos usuarios.

  • Método: POST
  • Entrada (JSON): { "username": "...", "email": "...", "phone": "...", "password": "..." }
  • Proceso:
    1. Recibe los datos del usuario en formato JSON.
    2. Valida que todos los campos estén presentes y que el email tenga un formato válido.
    3. Verifica si el email ya existe en la base de datos para evitar duplicados.
    4. Hashea la contraseña usando el algoritmo PASSWORD_DEFAULT de PHP. Esto es crucial para la seguridad, ya que nunca se guardan contraseñas en texto plano.
    5. Genera un token de verificación (aunque la lógica de envío de email no está implementada, el token se guarda para futura extensibilidad).
    6. Inserta el nuevo usuario en la tabla users.
    7. Devuelve una respuesta JSON con el estado del proceso.
// Línea clave: Hasheo de la contraseña
$hashed_password = password_hash($password, PASSWORD_DEFAULT);

// Línea clave: Inserción en la base de datos usando PDO con sentencias preparadas para prevenir inyección SQL
$sql = "INSERT INTO users (username, email, phone, password, verification_token) VALUES (:username, :email, :phone, :password, :token)";
$stmt = $pdo->prepare($sql);
$stmt->execute([...]);

Inicio de Sesión: api/login.php

Este script autentica a los usuarios existentes.

  • Método: POST
  • Entrada (JSON): { "email": "...", "password": "..." }
  • Proceso:
    1. Recibe el email y la contraseña.
    2. Busca un usuario con el email proporcionado en la base de datos.
    3. Si encuentra un usuario, utiliza password_verify() para comparar la contraseña proporcionada con el hash almacenado.
    4. Si la contraseña es correcta, inicia una sesión de PHP y almacena el id del usuario en $_SESSION['user_id']. Esta variable de sesión se usará en otras partes de la API para verificar que el usuario está autenticado.
    5. Devuelve una respuesta JSON de éxito o error.
// Líneas clave: Verificación de la contraseña y gestión de la sesión
$user = $stmt->fetch(PDO::FETCH_ASSOC);

if ($user && password_verify($password, $user['password'])) {
    // La contraseña es correcta
    $_SESSION['user_id'] = $user['id']; // Se establece la sesión
    ...
}

Cierre de Sesión: logout.php

Un script muy simple que destruye la sesión del usuario y lo redirige a la página de login.

// logout.php
<?php
session_start();

Blockchain

El núcleo de la aplicación. La lógica está encapsulada en dos clases principales dentro de la carpeta core/.

Clase Bloque: core/Block.php

Representa un único bloque en la cadena. Contiene todos los elementos esenciales de un bloque de blockchain.

  • Propiedades:
    • $index: La posición del bloque en la cadena.
    • $timestamp: La fecha y hora de creación.
    • $data: Los datos almacenados en el bloque (transacciones, mensajes, etc.).
    • $previousHash: El hash del bloque anterior, que enlaza la cadena.
    • $hash: El hash del bloque actual, calculado a partir de su contenido.
    • $nonce: Un número que se incrementa durante el minado para encontrar un hash válido.
  • Métodos Clave:
    • calculateHash(): Calcula el hash SHA-256 del bloque concatenando todas sus propiedades. Cualquier cambio en el contenido del bloque resultará en un hash completamente diferente.
    • mineBlock($difficulty): Implementa el algoritmo de Prueba de Trabajo (Proof of Work). Es un bucle que incrementa el $nonce y recalcula el hash del bloque hasta que el hash comience con un número específico de ceros, determinado por la $difficulty. Este proceso requiere una cantidad significativa de cómputo, lo que asegura la red.
// core/Block.php - El corazón del minado
public function mineBlock($difficulty) {
    // Bucle hasta que el hash cumpla con la dificultad (ej: empiece con "0000")
    while (substr($this->hash, 0, $difficulty) !== str_repeat('0', $difficulty)) {
        $this->nonce++;
        $this->hash = $this->calculateHash();
    }
}

Clase Cadena de Bloques: core/Blockchain.php

Gestiona toda la cadena de bloques, su integridad y la adición de nuevos bloques.

  • Proceso de Inicialización:
    1. Al crear una instancia, intenta cargar la cadena de bloques desde la tabla blockchain de la base de datos.
    2. Si la base de datos está vacía, crea el bloque génesis (el primer bloque de la cadena) y lo guarda.
  • Métodos Clave:
    • getChainFromDB() / saveBlockToDB(): Métodos privados que manejan la persistencia de la blockchain en la base de datos MySQL.
    • addBlock($newBlock): Añade un nuevo bloque a la cadena. Primero, establece el previousHash del nuevo bloque con el hash del último bloque de la cadena. Luego, llama al método mineBlock() del nuevo bloque para encontrar un hash válido. Finalmente, lo añade a la cadena y lo guarda en la base de datos.
    • isChainValid(): Un método crucial para la seguridad. Itera sobre toda la cadena y verifica dos cosas:
      1. Que el hash de cada bloque coincida con su contenido ($currentBlock->hash !== $currentBlock->calculateHash()). Esto previene la manipulación de datos en bloques antiguos.
      2. Que el previousHash de cada bloque coincida con el hash del bloque anterior ($currentBlock->previousHash !== $previousBlock->hash). Esto asegura que la cadena no ha sido rota o alterada.

Endpoints de la API de Blockchain:

  • api/get_chain.php: Devuelve la cadena de bloques completa en formato JSON.
  • api/mine_block.php: Recibe datos del frontend, crea un nuevo bloque, lo mina y lo añade a la cadena.

Conversor de YouTube

api/youtube_converter.php

Un endpoint simple pero potente para convertir URLs de YouTube en código de inserción (iframe).

  • Método: POST
  • Entrada (JSON): { "url": "..." }
  • Proceso:
    1. Recibe una URL.
    2. Utiliza una expresión regular (regex) para extraer el ID del video de diferentes formatos de URL de YouTube (youtube.com/watch?v=..., youtu.be/..., youtube.com/embed/..., etc.).
    3. Si se encuentra un ID, construye una etiqueta <iframe> estándar de YouTube y la devuelve en formato JSON.
// La expresión regular que hace la magia
$regex = '/(?:youtube\.com\/(?:[^\/]+\/.+\/|(?:v|e(?:mbed)?)\/|.*[?&]v=)|youtu\.be\/)([^"&?\/\s]{11})/';

Lista de Tareas (To-Do List)

api/todo.php

Este script es un endpoint RESTful completo para gestionar las tareas de un usuario.

  • Autenticación: Antes de cualquier operación, el script verifica que el usuario haya iniciado sesión comprobando $_SESSION['user_id']. Todas las operaciones de la base de datos se filtran por este user_id, asegurando que un usuario solo pueda ver y modificar sus propias tareas.
  • Manejo de Métodos HTTP:
    • GET: Obtiene y devuelve todas las tareas del usuario autenticado.
    • POST: Añade una nueva tarea. Recibe el texto de la tarea y lo inserta en la base de datos.
    • PUT: Actualiza el estado de una tarea (completada o no). Recibe el ID de la tarea y el nuevo estado.
    • DELETE: Elimina una tarea. Recibe el ID de la tarea a eliminar de la URL (?id=...).

Análisis del Frontend (HTML/CSS/JS)

El frontend es la cara visible de la aplicación. Está construido con HTML semántico, CSS para el estilo y JavaScript para la interactividad y la comunicación con el backend.

Páginas HTML/PHP

  • login.php / register.php: Contienen formularios HTML simples para la entrada de datos del usuario. Cada uno enlaza a su respectivo script de JavaScript para manejar el envío.
  • index.php: No muestra contenido. Su única función es comprobar si el usuario tiene una sesión activa. Si la tiene, lo redirige al dashboard.php; si no, al login.php.
  • dashboard.php: Es la página principal de la aplicación.
    • Verifica la sesión al principio para proteger la página.
    • Contiene la estructura HTML para el panel, incluyendo la cabecera, la navegación y las secciones para cada funcionalidad (Blockchain, Galería de YouTube, Lista de Tareas).
    • Carga el script js/dashboard.js, que es donde ocurre toda la magia interactiva.

Hoja de Estilos: css/style.css

Proporciona un diseño limpio, moderno y responsivo para toda la aplicación. Algunos aspectos destacados:

  • Estilos Generales: Define una tipografía moderna, colores base y un fondo suave.
  • Contenedores de Formularios: Centra los formularios de login/registro y les da una apariencia de "tarjeta" con sombras y bordes redondeados.
  • Dashboard: Estructura el panel con una cabecera fija (usando flexbox) y secciones bien definidas.
  • Visor de Blockchain:
    • .block: Da estilo a cada bloque individual con un fondo claro y bordes.
    • .hash: Utiliza una fuente monoespaciada para los hashes, mejorando la legibilidad.
  • Galería de YouTube:
    • #video-gallery-container: Utiliza display: grid para crear una galería de videos responsiva que se ajusta automáticamente al tamaño de la pantalla.
    • .video-wrapper: Utiliza la técnica del "padding-bottom" para mantener una relación de aspecto de 16:9 para los videos, asegurando que no se deformen.
  • Lista de Tareas: Da estilo a los elementos de la lista, diferenciando visualmente las tareas completadas (con texto tachado) y proporcionando un botón de eliminación claro.

Lógica del Cliente (JavaScript)

El JavaScript de la aplicación utiliza la API fetch para todas las comunicaciones asíncronas con el backend y manipula el DOM para mostrar los datos de forma dinámica sin necesidad de recargar la página.

Scripts de Autenticación: js/login.js y js/register.js

Ambos scripts siguen un patrón similar:

  1. Añaden un "event listener" al evento submit del formulario.
  2. Previenen el comportamiento por defecto del formulario (que recargaría la página) con e.preventDefault().
  3. Recopilan los datos del formulario.
  4. Realizan una petición fetch al endpoint de la API correspondiente (api/login.php o api/register.php) con el método POST y los datos serializados en formato JSON.
  5. Procesan la respuesta JSON del servidor, mostrando un mensaje de éxito o error al usuario.
  6. En caso de éxito, redirigen al usuario a la página de login o al dashboard después de un breve retardo.
// Patrón de fetch en js/login.js
fetch('api/login.php', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json'
    },
    body: JSON.stringify(data)
})
.then(response => response.json())
.then(result => {
    // Actualizar el DOM con el mensaje de 'result.message'
    if (result.status === 'success') {
        window.location.href = 'dashboard.php';
    }
})

Script del Panel: js/dashboard.js

Este es el script más importante del frontend. Orquesta todas las funcionalidades del panel principal.

  • Carga Inicial: Utiliza el evento DOMContentLoaded para asegurarse de que el script se ejecuta solo después de que todo el HTML ha sido cargado.
  • Funcionalidad de Blockchain:
    • fetchChain(): Hace una petición GET a api/get_chain.php y luego llama a renderChain() para mostrar los bloques.
    • renderChain(): Itera sobre los bloques recibidos y crea dinámicamente los elementos HTML para cada uno, inyectándolos en el DOM.
    • Añade un "event listener" al botón de minado. Al hacer clic, envía los datos del nuevo bloque a api/mine_block.php y, si tiene éxito, llama a fetchChain() de nuevo para refrescar la vista.
  • Funcionalidad de Galería de YouTube:
    • Escucha el clic en el botón "Add Video".
    • Envía la URL del input a api/youtube_converter.php.
    • Recibe el código del iframe y lo añade a #video-gallery-container, haciendo que el nuevo video aparezca instantáneamente.
  • Funcionalidad de Lista de Tareas:
    • Implementa un sistema CRUD completo en el frontend.
    • fetchTasks(): Obtiene las tareas del usuario desde api/todo.php.
    • renderTasks(): Dibuja la lista de tareas, creando los checkboxes, el texto y los botones de borrado para cada una.
    • Los "event listeners" en los botones de añadir, los checkboxes y los botones de borrado llaman a funciones que realizan peticiones POST, PUT o DELETE al endpoint api/todo.php y luego refrescan la lista llamando a fetchTasks().
